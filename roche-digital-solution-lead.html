Retrieval-Augmented Search — Work Sample

Semantic search over trial protocols, with the governance built in from the start

Jane Natividad  ·  jane-natividad.github.io  ·  linkedin.com/in/jane-natividad

Most RAG demos hide the interesting part: what got retrieved, why, and whether the model actually used it. In a regulated data environment that's not a UI nicety, it's the whole question — a clinical evidence tool nobody can audit is a tool nobody can trust with a real decision. So this one shows its work at every step: ask a question, watch the deterministic retrieval run first (works with zero setup), then optionally hand the retrieved excerpts — and only those excerpts — to Claude for a grounded, cited synthesis.
The pipeline
1 · RetrieveDeterministic TF‑IDF search ranks the synthetic protocol corpus against your question. No model, no key, no network call.
2 · GroundOnly the top-matched excerpts are kept as context — the full corpus never leaves this step.
3 · GenerateIf you add a key, Claude synthesizes an answer from that grounded context only, instructed to say so if it isn't enough.
4 · Cite & flagEvery synthesized claim is tied to a protocol ID, and the output is labeled as needing human review before it informs anything real.

This is the "agentic workflow" pattern in miniature: a fixed, inspectable sequence of steps with a grounding constraint at each hand-off — not an autonomous agent making its own calls about what to search or what to trust.

Governance, by design not by policy doc

  

    

      
1

      
Data minimizationThe model only ever sees the small set of excerpts retrieval already ranked as relevant — never the full corpus, never your raw question history.

    

    

      
2

      
Provenance on every claimThe synthesis is instructed to cite a protocol ID for every statement, and to say "not enough in the retrieved set" rather than fill the gap from general knowledge.

    

    

      
3

      
Inspectable contextThe exact text handed to the model is one click away, above — nothing about what it "saw" is hidden inside the request.

    

    

      
4

      
Synthetic data onlyAll 12 protocols are fictional, generated for this demo. No real patient data, real trial data, or proprietary Roche information is used anywhere on this page.

    

    

      
5

      
Human review, explicitly flaggedEvery synthesized answer is labeled as a work sample requiring scientific and regulatory review — this page automates retrieval and drafting, not the decision.

    

  


  
What this deliberately does not do

  
    
    
  • No real embeddings or vector database — retrieval is TF‑IDF cosine similarity over 12 records, enough to demonstrate the pattern honestly, not benchmarked at production scale or corpus size.
    • 
    
  • No connection to any real system — not ClinicalTrials.gov, not a Roche system, not any regulated data source. Everything here is offline and synthetic.
    • 
    
  • No autonomous decisions — the model never chooses what to retrieve, what to trust, or what to do next. Every step in the pipeline above is fixed by the code, not by the model.
    • 
    
  • No fine-tuning, no persistence, no logging of anything you type — this is a static page with client-side JavaScript, nothing is sent anywhere except the one optional call to Anthropic if you supply a key.
